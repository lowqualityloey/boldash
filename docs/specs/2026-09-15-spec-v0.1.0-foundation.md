## 1. Problem, Metrics, Non-Goals

### 1.1 Problem
Boldash has architecture and contract documentation but no runtime. v0.1.0 must prove the core claim end-to-end: *the LLM proposes JSON; deterministic code validates it, owns state, and returns exit codes that can block work* — before any host-adapter magic exists.

### 1.2 Measurable success criteria (exit = §16 Phase 1)
| Metric | Target |
|---|---|
| E2E user journey | `init → route → state transition → verify` all work from CLI on a clean fixture repo |
| Route validation latency | < 25 ms per proposal (deterministic, no I/O beyond registry read) |
| `verify` overhead | < 2 s excluding commands the contract itself declares |
| Agent-facing payload size | route success ≤ 80 tokens; failure ≤ 140 tokens (P9) |
| Test suite | `npm run verify` (lint + typecheck + tests) green in CI on every push |
| Schema discipline | 100% of CLI JSON output validated against `schemas/*.schema.json` in tests |

### 1.3 Explicit non-goals (deferred by design — do not creep)
- Policy engine (`policy check`), `doctor`, `explain`, `checkpoint`, `diff`, `evidence` query commands → Phase 2/3 (§16).
- Host adapters (Claude/Cursor hooks) → Phase 2/3. v0.1.0 ships the **generic adapter** only.
- `worktree` command, leases/claims, multi-agent subagent protocol → Phase 3.
- Event log beyond minimal audit lines; evidence store layout → Phase 3.
- Benchmark suite, plugin API, workflow registry service → Phase 4.
- Custom check types, localization, Windows-parallel init scripts (CI stays Linux-first; Windows support = follow-up issue).

## 2. System Context & Deep Modules

### 2.1 Request lifecycle (v0.1.0 slice)
```
Agent/human ──► CLI (thin: parse argv → call engine → format) ──► Engines (pure-ish) ──► .boldash/** (files)
   route.json ─► Router: 7-step pipeline ─► ResolvedRoute ─► StateEngine: create task ─► tasks.json + events.jsonl
   verify    ─► VerificationEngine: load contract + state ─► run 5 check types ─► gate result (exit 0/1/2/12)
```

### 2.2 Deep modules (deletion test applied)
| Module | Interface (what it hides) | Deletion verdict |
|---|---|---|
| `core/router` | `resolveRoute(proposal, ctx) → Result<ResolvedRoute>` — hides schema validation, registry lookup, risk→level map, capability checks | Keep — concentrates all routing law |
| `core/state` | `TaskStore` — get/list/transition/addRequirement/addEvidenceRef; hides atomic write (temp+rename), optimistic versioning, schema migration | Keep — single writer to `tasks.json` |
| `core/verification` | `verifyTask(task, contract) → GateResult` — hides check execution, timeouts, output capture, redaction | Keep — the gate itself |
| `core/workflow` | registry + v1 importer — hides pack format, manifest validation | Keep |
| `core/evidence` (v0.1.0 lite) | append events; write evidence payloads | Keep, minimal |
| `shared` | `Result<T,E>`, error catalog (code→exit), fs helpers | Keep — no logic, only types/constants |
| `adapters/generic` | capability probe, briefing-file append | Keep — thins CLI of host knowledge |

**Deliberately NOT modules in v0.1.0:** no "policy" module (rule data is inline constants in risk→level map), no "cache", no service layer under engines. Shallow pass-throughs would violate the deletion test.

### 2.3 Seams & test surfaces
- **Seam 1 (top):** CLI invocation against a **fixture repository** on real temp FS (AGENTS.md rule: do not mock the filesystem). Golden tests assert `--format json` payloads + exit codes.
- **Seam 2 (unit):** each engine takes parsed inputs and returns `Result`; no engine imports another engine except CLI → engines.
- Clock injected (no `Date.now()` in engines; the CLI supplies timestamps) → deterministic transition/event tests.

## 3. Domain Model & Contracts

### 3.1 Entities (TypeScript mirrors JSON schemas; schemas are canonical — P7)
- **RouteProposal** — as `schemas/route.schema.json` in `docs/routing-contract.md` (verbatim adoption).
- **ResolvedRoute** — `{ workflow, level, requirements{task_record,specification,tests,review,human_approval} }`.
- **Task** — `{ id: TASK-NNN, title, type, risk, level, status: proposed|planned|implementing|verifying|complete|blocked|failed, version: int, requirements: [{id, text, status, evidence: [evt_id]}], evidence_refs, owner?, created_at, updated_at }`.
- **WorkflowPack** — `workflows/<name>/{manifest.yaml, protocol.md, done.schema.json}`; built-in packs: `feature`, `bugfix`, `docs`, `chore` (minimum registry for §16).
- **Event** — one JSONL line `{ id: evt_NNNN, ts, task, action, actor, payload }` appended on create/transition/verify.
- **GateResult** — `{ status: VERIFIED|BLOCKED, checks: [{name, pass, detail}], exit: int }`.

### 3.2 State layout — **DECISION-v010-001 (resolves ARCHITECTURE §18 Q1)**
Single `.boldash/state/tasks.json` with `{ schema_version: 1, tasks: [...] }`.
Grounded in the existing corpus: `docs/getting-started.md` §What was created, `docs/faq.md` §State, `docs/cli-reference.md` §init. Simpler atomicity for v0.1.0; per-file scaling deferred until proven unnecessary. **Owner: maintainer (confirm on approval).**

### 3.3 State-schema evolution policy (Expand-Contract, applied to JSON state)
1. **Expand:** new fields must be optional or defaulted; readers tolerate unknown fields (`additionalProperties: true` at file root, validator strict per-entity).
2. **Backfill:** `init`/first write of a newer writer migrates old files in place, event logged (`state.migrated`).
3. **Contract:** a reader encountering `schema_version >` supported returns `SCHEMA_VERSION_MISMATCH` (exit 2) — never silent corruption, never auto-downgrade.
No destructive change can ever ship in a minor release. This is the state-file analog of zero-downtime migrations.

### 3.4 CLI contracts (v0.1.0 surface — trimmed from cli-reference.md)
| Command | Flags | Exit codes |
|---|---|---|
| `init` | `--profile <p> --host <name> --force` | 0, 2 |
| `route` | `--input <path> \| --json '<inline>' \| stdin`, `--create` | 0, 2, 3 |
| `state get/list/transition` | filters `--status --risk --type --limit` | 0, 2, 4 |
| `state requirement add` | `TASK --id R1 --text "…"` | 0, 2, 4 |
| `state evidence add` | `TASK --type <kind> --ref <evt>` | 0, 2 |
| `verify` | `TASK \| --all` | 0, 1, 2, **12** |
| `workflow list/validate/import` | `import <path>` | 0, 2, 3 |
| `--format json` on all; global flags per cli-reference | | |

**Amendments to surface docs (spec-corpus findings resolved by this RFC):**
- `verify` exit table must include **12** (command timeout) — `errors.md` is authoritative; patch `cli-reference.md`/`verification-guide.md` (§16 issue).
- `timeout_ms` added as a valid property of `must_pass`/`must_not` checks in the verification meta-schema.
- `state requirement add` documented in cli-reference (transition guard `STATE_MISSING_REQUIREMENT` implies it).
- `state claim` and `--no-cache` **excluded** from v0.1.0 (§18: leases = Phase 3; caching = Phase 3).

### 3.5 Error contract
`docs/errors.md` adopted verbatim as the v0.1.0 catalog; code→exit mapping table becomes a **tested constant** in `shared/errors.ts`. Rule: codes stable forever; messages mutable; every code ships with a test that produces it.

## 4. FMEA (Phase 1 failure modes)

| Failure scenario | Prob / Sev | Detection | Mitigation | Recovery |
|---|---|---|---|---|
| Torn `tasks.json` (crash mid-write) | Low / High | JSON parse error on next read | temp-file + atomic rename (only write path) | restore from Git; state is committed |
| Concurrent edits (two agents) | Med / Med | version mismatch on write | optimistic locking → `CONCURRENT_MODIFICATION` exit 4 | re-read + retry (documented agent loop) |
| `init` outside a Git repo | Med / Low | explicit check | refuse with structured error (`--force-gitless` later) | — |
| Verification command hangs | Med / Med | 300 s default timeout | kill process tree → exit 12 + TIMEOUT event | contract author tunes `timeout_ms` |
| Contract runs destructive command | Low / High | cannot be prevented in-process | **design**: only declared commands run; docs + `SECURITY.md` §1 state it; importer marks unknown v1 workflows non-executable until human edits contract | human review of `done.schema.json` |
| Evidence contains secrets | Med / High | redaction scan before write | best-effort patterns → `EVIDENCE_REDACTION_FAILED` (exit 10) rather than write raw | manual review |
| `.boldash/` accidentally gitignored by host project | Med / Med | `init` warns; FAQ guidance | warn + document P6 rationale | commit anyway (advisory) |
| v1 import mis-parses a workflow | High / Low | importer emits conservative stub (no executable checks) + `import-report.md` | never auto-generate runnable `command` checks from prose | human hardens contract |
| Windows path separators | Low / Med | CI is Linux | POSIX-only in v0.1.0; issue filed; `path` module everywhere, no string joining | Phase 2 follow-up |
